# L08 · Трейс як документ

Кіт до лабораторної L08 курсу з тестування LLM-агентів. Ви проганяєте **весь
діалог** бота підтримки PayPilot у справжній моделі і читаєте трейси його
кроків як один документ: скільки разів крок звертався до моделі, які
інструменти викликав і скільки разів однаково, скільки токенів прочитав (і
скільки з них з кешу), скільки тривав і скільки коштував.

Мока тут немає: на L08 нас цікавить саме ціна і час живих кроків. Ціну ранер
рахує сам — з токенів кожного спана `llm.call` і прайсу в `prices.json`, — а не
бере з відповіді `/chat`.

Python локально не потрібен: ранер іде в Docker, у голому
`python:3.12-slim`, лише стандартна бібліотека.

## Що зробити, коротко

Корінь курсу — `~/paypilot`: стенд у `~/paypilot/paypilot-stand`, цей
репозиторій — у `~/paypilot/l08`.

1. Стенд на коміті `325e2dd` або новішому, запущений без проксі L07:
   `cd ~/paypilot/paypilot-stand && git pull && docker compose up -d --force-recreate stand`.
2. Склонувати кіт: `git clone https://github.com/sergeytkachenko/paypilot-l08-eval.git ~/paypilot/l08`.
3. Прогнати один сценарій з таблицею кроків:
   `cd ~/paypilot/l08 && docker compose run --rm eval --scenario B1 --table`.

## Що потрібно

- Docker Desktop (macOS, Windows) або Docker Engine з compose (Linux).
- Локальний стенд `~/paypilot/paypilot-stand` на `http://localhost:8000`.
  Ранер скидає базу стенду перед кожним прогоном, тому на спільному стенді
  його не запускайте.
- Ключ моделі в `.env` стенду і `LLM_PROVIDER=openrouter` (або інший
  справжній провайдер). На `mock` ранер зупиняється: токенів і ціни там немає.
- Діалог із семи кроків коштує близько $0.004–0.006 на OpenRouter з
  `anthropic/claude-haiku-5.5`; повний прогін трьох сценаріїв по 5 разів на
  обох умовах — близько $0.1.

## Що в репозиторії

| Файл | Що це |
|---|---|
| `scenarios/*.json` | три сценарії: репліки діалогу, умови baseline і defect, перевірки |
| `run_dialog.py` | ранер: проганяє діалог, бере трейс кожного кроку, рахує ціну, перевіряє |
| `prices.json` | прайс моделі за мільйон токенів і множники кешу; параметр, а не константа |
| `docker-compose.yml` | сервіс `eval` |

## Як влаштований сценарій

```json
{
  "id": "B1",
  "dimension": "orchestration",
  "level": 1,
  "customer_id": "CUS-0003",
  "gate": "daily",
  "runs": 1,
  "conditions": {
    "baseline": {"profile": "clean", "defects": ""},
    "defect":   {"profile": "clean", "defects": "D14"}
  },
  "turns": [
    {"user": "Hi, which accounts do I have?"},
    {"user": "Can you show my recent transactions?"}
  ],
  "assertions": [
    {"kind": "tool_called", "step": 2, "tool": "get_transactions"},
    {"kind": "identical_tool_calls_max", "step": "all", "max": 1}
  ]
}
```

- Формат той самий, що в кіті L07, тільки всі кроки живі, а перевірки
  дивляться на будь-який крок (`step`) або на весь діалог.
- `conditions` вмикаються заголовком `X-Stand-Settings` на кожен запит:
  `profile`, `defects`, `summarize_after` (з якого кроку стенд згортає
  історію). Профіль стенду ранер не перемикає.
- `gate` і `runs` — як на L07: `daily` — вердикт детермінований, щойно дія
  відбулася, `runs: 1`; `release` — залежить від того, що сказала модель,
  `runs: 5`. `--gate daily` запускає лише daily-сценарії стільки разів, скільки
  сказано в `runs`; без `--gate` — один раз.
- `level` і `dimension` ранер не читає; це ваша розмітка за драбиною й
  вимірами.

## Перевірки

| `kind` | Що перевіряє | Рівень драбини |
|---|---|---|
| `tool_called` | на кроці `step` викликано інструмент `tool` (передумова) | 1 |
| `identical_tool_calls_max` | у межах одного кроку не більше `max` викликів з однаковими назвою й аргументами | 1 |
| `first_call_input_tokens_max` | перший виклик моделі на кроці `step` прочитав не більше `max` вхідних токенів | 2 |
| `dialog_tokens_max` | сума вхідних і вихідних токенів усіх кроків | 2 |
| `dialog_latency_ms_max` | сума `duration_ms` усіх кроків | 2 |
| `dialog_cost_usd_max` | ціна діалогу, порахована зі спанів за `prices.json` | 2 |
| `summary_contains` | переказ згортки (`summary.text`) містить усі `values` | 3 |

## Таблиця кроків (`--table`)

```text
  step calls retry same 1st in      in  cached   out      ms   $ trace   $ usage replay
     1     2     0    1   2601    5349    5028   151    3150  0.000158  0.000158 False
     2     9     7    8   2844   28080   22626  1959   17260  0.001751  0.000345 False
```

| Колонка | Звідки |
|---|---|
| `calls` | кількість спанів `llm.call` у трейсі кроку |
| `retry` | з них повтори оркестрації (`agent.loop_step: retry-N`) |
| `same` | найбільша кількість однакових викликів інструмента в кроці |
| `1st in` | вхідні токени першого виклику моделі в кроці |
| `in`, `cached`, `out` | суми `gen_ai.usage.*` по всіх `llm.call` кроку |
| `ms` | `duration_ms` кореня `agent.request` |
| `$ trace` | ціна, порахована зі спанів за `prices.json` |
| `$ usage` | поле `usage.cost_usd` відповіді `/chat` — для порівняння |
| `replay` | `context.replay_active` на корені |

Якщо `$ trace` і `$ usage` розходяться — вірте трейсу: поле відповіді не
враховує повтори оркестрації. Токенів згортки історії немає ні там, ні там.

прогонів на умову.

| Сценарій | baseline | defect | defect / baseline (медіана) |

| **B2** · D15, CUS-0004, 7 кроків | 5/5: перший виклик кроку 6 читає 5 618–5 824 токени | 0/5: 6 609–7 555; `replay` true з кроку 2 | токени ×1,24, час ×1,06, ціна ×1,33 |
| **B3** · згортка на `lesson-05`, `summarize_after: 2` | 5/5: переказ на кроці 3 містить `TX-0401` і `duplicate_charge` | 0/5: переказ без номера транзакції і з іншим кодом або без коду | токени ×1,28, ціна ×1,31 |

## Phoenix

Phoenix (`http://localhost:6006`) показує те саме дерево і токени
(`llm.token_count.*`), але **не справжній час**: стенд віддає йому дерево вже
після ходу, і всі спани там тривають частки мілісекунди. І **не ціну**: моделі
стенду немає в його таблиці цін. Час і гроші — з таблиці ранера.

## Пастки

- **Спільний стенд.** Не запускайте ранер на спільному стенді: він скидає базу.
- **Проксі L07.** Якщо стенд досі запущено з `stand.override.yml` з L07,
  запити йдуть через мок; перезапустіть стенд без override (крок 1).
- **Мова.** Якщо в діалозі змішано англійську й українську, стенд дописує в
  кінець промпту правило мови відповіді, і кеш ламається.
- **Довгі діалоги.** За замовчуванням після 8 кроків стенд згортає історію;
  вхід моделі після згортки різко падає. Для порогів беріть кроки до згортки
  або задайте `summarize_after` явно.
- **Порожній результат.** D14 спрацьовує лише на порожньому результаті
  інструмента. На стенді він є в одного клієнта: CUS-0003, рахунок ACC-1004.
